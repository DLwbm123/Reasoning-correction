# 声明支持更新的 CPU 原型检查

性质：必要的语义工程检查，不是新的医疗/模型性能实验，也不是冻结后的效果验证。
旧的 E0/D1/D2、其代码和报告均未改写；没有 GPU 调用或源病例处理。

新增 `support_state.py` 与 `test_support_state.py`。设计及新颖性边界见
`STATE_REVISION_DESIGN.md`。原型表达有符号来源记录、多个充分支持、显式撤回与冲突；
不把未知当错误，不从语言模型父子边推导充分逻辑规则，不实行最新来源自动胜出。
本原型的来源白名单是输入接纳约束，不是来源事实正确性的认证器。

执行 `python3 -m unittest -v test_support_state.py`：6 项通过。
检查覆盖替代支持、最后支持失效、冲突阻断、显式负支持、作用域/来源/事务失败和循环拒绝。
其中 4 个正负证据位形成 16 个证据集合，枚举全部 256 个有序旧/新集合组合，增量状态与
同一声明系统的从头重算相等。该枚举只改变 a/b 两原子的记录，不能推广成任意图证明。
手写反例还有独立 u 支持，检查旧的整块后继隔离会遗漏的支持替代。

从头重算检查复用了同一求值器，是一致性不变量；它不是独立临床评估，也不是算法正确性
的完整证明。多个手写预期用于检查关键语义。尚不支持默认规则、循环、不确定度校准、
自动依赖抽取、观察选择、病例身份匹配或临床语言输出验收。

重要结论不是性能提升：正确增量状态和同信息完整重算理应相同；若答案本身完全由像素
注释和程序规则决定，确定求解与渲染是必要强对照，不能拿 VLM 纠错包装成独有逻辑收益。
经典 ATMS、MedFH、Belief-R 与 DeReLab 进一步限制了当前候选的新颖性，详见设计中的
直接来源。当前尚未满足新小型 GPU 研究的实质机制/独立验证准入。

本阶段公开代码、设计和检查汇总；没有新增逐病例内容或临床真值。
