# 两台现有环境的吞吐短测

同一 Qwen2.5-VL-7B checkpoint、相同六个请求，固定输入处理和 128 输出 tokens，
预热后各测 18 次。实际输入/视觉/输出 token 长度逐请求一致。没有参考答案或准确率评价。

| 运行环境 | 总输出 tokens | 测量时间 | 吞吐 |
|---|---:|---:|---:|
| RTX 3090；torch 2.2.1+cu121 / transformers 4.49.0 | 2304 | 65.07 秒 | 35.41 token/秒 |
| RTX PRO 5000 72GB Blackwell；torch 2.7.1+cu128 / transformers 4.51.3 | 2304 | 66.34 秒 | 34.73 token/秒 |

本次 Blackwell/3090 吞吐比为 0.981，未观察到明显速度优势。不能据此判定 Blackwell 硬件
更慢：软件栈不同，且 GPU 共享负载未隔离，Blackwell 的部分请求明显抖动。这里只比较现有
可用环境；没有安装新依赖、调整功率、终止他人进程或进行优化搜索。

3090 的原 6 号卡在测速前显存不足，未加载模型即退出；保留该预检记录后，在显存充足的
同型号 3 号卡执行。pro5000 的中性解释器第一次使用了错误的 venv PYTHONHOME，尚未加载
模型即退出；修正为原解释器的 base prefix 并保留原日志，随后完成测量。两次入口问题没有
重跑任何已完成的医学试验，也没有改变 E0 的预算、输入或结论。

后继 32 例接口诊断选择 pro5000，理由是当前吞吐接近且显存余量较大，已有权重可以只读
复用；不声称迁移会加速，不将本短测当作医疗性能证据。输入图像和内容不公开，公开仅含
请求索引、token 长度、耗时、模型/软件版本及汇总。
