# 命题修订接口：实现与绑定检查

2026-11-08。本次为本机实现验证，没有服务器访问、真实模型调用、训练、新数据扫描或新增专家裁决，不是新医疗性能实验。已完成G1–G8及其结果保持冻结。

## 已实现的具体执行约束

新增`assertion_revision.py`，独立于旧`mechanism.py`和完成的运行入口。

- 输入只有case/view/question、原声明和程序登记证据。逐层字段白名单检查；reference等额外字段在调用补全前拒绝。最终答案是独立声明槽，不允许额外自由文本答案绕过事务。
- 原声明ID与原文保留在审计账本。KEEP直接复制原声明；REPLACE/ADD必须用唯一新ID；每条旧声明必须恰好处理一次，不能静默删除。缺项、重复、覆盖旧ID或多个输出答案均拒绝整笔候选。
- WITHHOLD明确记为insufficient/conflict并保留历史，不变为“错误”。父边仅存为提议；父节点被withhold不会自动把下游判假或认证为真。未知父ID、循环关系拒绝。
- 支持条目绑定确切声明、登记证据、病例/视图、source与Unicode字符区间；引文必须等于该区间。新声明必须有引用。该版本只有单视图，source_id须与view_id一致，不处理裁剪或跨视图配准。
- 模型不能自报expert。包括SUPPORTED在内的全部关系由程序标成`model_proposal`、语义未审；结构通过的候选始终`semantic_eligible=false`。adequate/引用存在没有被升级为医学正确性。
- 严格解析整个JSON对象，拒绝重复键、根数组、尾部文本等；不事后包装或修补格式。失败保存原请求、原文、可解析的原提议和错误，不返回半笔应用结果。

`execute_revision(request, complete, receipt_path)`贯通请求序列化→fresh messages→一次补全回调→原始字符串解析→整笔绑定→私有receipt写盘。receipt以排他模式在调用前创建；已存在时不再次调用，无自动重试。补全异常也保存失败记录。调用方仍须配置真实模型、实际图像绑定、tokens/超时/存储守护和成本记录；本次没有接入Qwen生成或执行实际图像forward。这里的端到端检查是可执行适配器与测试补全回调，不声称真实模型预检已通过。

这修复的是“接口允许在旧ID下偷偷换命题”的执行缺口，不会识别同义/蕴含关系，也不会判断一条新命题是否临床正确；不自动修补已有八例或追改旧指标。原声明留在账本与可在部署答案中肯定是不同状态。

## 必要检查与结果

10项本机检查通过：精确保留与结果隔离副本；新增/替换；未知历史与下游不自动反驳；缺项/冲突/旧ID覆盖的原子拒绝；标签/病例/视图/源错配阻止调用；Unicode引文/未知引用/伪造assessor；父关系与答案绕过；严格JSON失败留存；实际回调请求响应和排他receipt；补全/解析失败无重试留存。两次实现增补后的复测用于新发现边界，未重跑旧原型或旧数据审计。

检查使用人工编写的一般文本和临时文件，未读取病例、GT、原图或旧分数。没有发生临床纠错或“10/10模型审查正确”的结果；该计数是测试方法数。旧支持状态六项检查未重复运行。

复现：`python -m unittest -v test_assertion_revision`。实验运行仍须中性入口；上述是开发检查命令，不是GPU启动命令。
